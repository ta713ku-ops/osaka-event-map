# UI再評価：読むための一覧から、出かけたくなる入口へ

## 結論と対象

ユーザーの指摘を受け、2026-10-01の公開版 `580dd36` を再点検した。今回の対象はホーム・一覧・詳細・ナビゲーションのUIのみ。イベントの件数、収集先の追加、情報の正確性をUIの優位性として加点しない。

現状は検索しやすいが、写真・場の気配・画面のリズムによって出かけたくなる体験が弱い。今回の目的で「祭りどころをUIでも超えた」とは扱わない。前回のGauntletは当時の基準による記録として保存し、没入感を重視した今回の受け入れ判定の代用にしない。

確認した公開画面は https://ta713ku-ops.github.io/osaka-event-map/?v=580dd36 と https://www.matsuri-dokoro.jp/ja 。比較先の掲載地域・件数・広告量は没入感の採点に使わない。公開ホームは1280×720、390×844、ユーザーの狭いブラウザ表示を観察し、なんば雲海の詳細を390×844で観察した。ブラウザ幅の変更直後の不安定な画像は判定に使わず、実際の表示幅も確認した。

Solによる設計レビューと、Luna・推論maxによる独立批評（固定画像12枚を実見）でも、操作・注記が写真より先行し、画面のリズムと期待感が不足する点が一致した。今回は再評価であり、新しいGauntlet勝利を記録したものではない。比較先PCの保存画像の白抜けは減点に使わず、ライブ画面では待機後に地図背景が描画されたことを確認した。候補の保存済み詳細画像では代替表示になっているが、今回の公開なんば詳細では実画像が読み込めたため、現在も画像がないとは扱わない。

## デザインの基準

ベースは `awesome-design-skills` の **storytelling**。写真・短い言葉・スクロールの順序で「発見→興味→参加判断」を作る。別のデザインシステムとは混ぜない。既存の日本語ブランド、配色、読みやすさを優先し、プリセットの英字フォントや青・紫へ機械的に置き換えない。

- 色：既存の生成り、墨色、朱色を継続。大きな写真の区画と静かな情報の区画に強弱をつける。
- 文字：見出しは日本語明朝系、操作・本文は日本語ゴシック系。スマホの主見出し32〜40px、本文14〜16px。小さな英語ラベルの連続は避ける。
- 余白：8px単位。スマホ本文の左右16〜20px、区画間32〜48px。余白のすべてをカードの均一な高さに使わない。
- 写真：イベント写真、告知ポスター、画像なしを区別する。ポスター全文を切り落とす拡大、低解像度画像の無理な引き伸ばし、別イベントの写真による穴埋めをしない。公式の写真が不足する場合は構図を調整する。
- 動き：意味のある入口の演出を一つに絞る。大きな移動、常時ズーム、無関係な点滅は避ける。自動切替は読む余裕を設け、停止操作、キーボード、画面外停止、reduced-motionを維持。
- 行動：主役区画の主な行動は一つ。地図・検索・保存は常に到達可能にし、全部を主役の上に並べない。
- 内容：開催中止、受付終了、予約必須、料金の重要条件は隠さない。信頼性は必要な場所に必要な情報を出すことで保つ。

## 提案するホームの順序

1. 小さなヘッダー：ブランド、最小限のナビ。
2. 写真の主役：公式の実像、短い誘い、イベント名、日付、一つの詳細導線。縦画像・ポスターの場合は専用の構図。
3. 短い検索導線：検索窓と今日・週末等の少数の入口。日付・エリア・並び順・詳細条件は検索結果の操作へ。
4. 季節の特集：写真と、そこでできることを一言で伝える。
5. 今日・週末のイベント：主役と異なる小さなカード。画像なしは写真用の広い空箱を作らない。
6. 場所から探す：大阪の場所とのつながりを地図で示し、実際の地図へ移れる。
7. 全件・検索結果への入口：ホームの長い全件一覧との重複を整理する。
8. 小さなフッター：サイト案内、情報源・更新について。収集の内部状態はここから必要な人が参照する。

## 再評価の受け入れ基準

優位性の評価と動作確認を別々に行う。件数やテスト合格によって見た目の負けを補わない。

1. **最初の5秒**：どんな場所・体験に出会えるか、写真と短い言葉から想像できる。
2. **現地の気配**：写真が主役になっている。代替画像・ポスターでも、データの空欄を埋めただけの画面に見えない。
3. **画面のリズム**：主役、特集、一覧、地図の見せ方に意図した違いがある。
4. **言葉の自然さ**：一般向けの入口に収集・監視・未確認候補等の運営用語がなく、根拠のない煽りもない。
5. **操作との両立**：没入感を見せるために検索・戻る・保存・経路・必要な参加条件を犠牲にしていない。
6. **独立比較**：同じ幅、画像読込後、ホーム・一覧・詳細と短い時系列を匿名化して批評する。没入感と操作の明快さを別々に判定し、混合の一点評価で勝利にしない。
7. **利用者の実感**：独立批評だけで完了にせず、ユーザーが今回求める方向と合うか確認する。完成後の主観評価は自動テストで代替できない。

動作ゲートは320/338/390/768/1280幅のはみ出し・ヘッダー・長い名称・縦画像・ポスター・画像欠損、ロード/空/エラー、検索→詳細→保存→戻る、詳細URL再読込、地図、キーボード、見えるフォーカス、44px以上の操作対象、reduced-motion、型検査・適切な既存テスト・ビルド。実機未確認の項目は区別する。
