## 実装結果

- 地図ピン・左側一覧・下部候補カードから、旧モーダルを挟まず共通の詳細URLへ直接遷移する。
- 詳細と関連イベントの遷移は履歴を1件追加し、戻る・進む・同一タブのリロードに対応する。直リンク時の画面内の戻るはホームへ移動する。
- 検索条件、地図の中心・ズーム、展開件数、スクロール、選択元のフォーカスを復元する。ホームの展開件数も保存対象とした。
- EventSheetと専用テスト・CSSを削除した。絞り込みとプロフィールの共有背景・スタイルは維持した。
- 座標なしイベントはピンのみ除外し、一覧・候補・詳細では引き続き利用できる。
- サブエージェント3名を `gpt-6-luna` / `max` で起動し、地図処理、旧UI整理・Appテスト、履歴レビューを分担した。親が差分を確認し、統合・全体テスト・ブラウザ操作を実施した。

## 検証中に修正した点

1. 非表示で作られた地図を再表示すると中心が半画面分ずれる問題を修正。サイズ再計算後に保存済み中心・ズームを適用し、その途中の値を保存しない。
2. LeafletがEnterをクリックへ変換するという前提を撤回。ピンの実DOMでEnter・Spaceを処理し、キーリピートによる重複を防いだ。
3. 通信失敗時の短いエラー画面で保存スクロールを上書きしないよう、データ取得成功まで復元を保留した。
4. スクロール直後にブラウザで戻った場合の最終位置をsessionStorageで補助保存し、戻る先の再読み込み後も進む操作で復元できるようにした。

## 確認範囲

- コミット・push・公開は未実施。公開サイトへの反映確認は含まない。
- iPhone/iPadの実機SafariおよびVoiceOverは未確認。
- sessionStorageが使用できない環境では、通常の履歴とメモリで復元する。スクロール直後に戻る→再読み込み→進むという操作では、最後の保存から120ms未満の位置変更が失われる場合がある。
