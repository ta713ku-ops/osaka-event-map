# どこいこ大阪 イベント詳細ページ方針 v3

## 目的

一覧では軽快に探し、詳細ページでは「どんなイベントか」「いつ・どこで開催されるか」「料金・予約・雨天対応」「どう行くか」を判断できる状態にする。公式情報を中心とし、取得できない事実は推測で補わない。

## 表示と遷移

- ホーム・通常一覧・地図ピン・地図の左側一覧・地図下部の候補カードから、1イベント1URLの独立詳細ページを直接開く。同じイベントは入口にかかわらず同じ公開URLと内容を使い、地図の簡易プレビューを挟まない。
- 詳細ページの関連イベントも同じ詳細遷移を使う。詳細を新しく開く操作は履歴に1件追加し、同じURLを連打した場合は重複した履歴を作らない。
- 画面内の戻るとブラウザの戻る・進むで、URLと表示を一致させる。戻った画面では検索語、日付条件、詳細フィルター、距離計算の起点、スクロール位置、地図の中心・ズーム、一覧と候補のスクロール位置・展開件数、選択元のフォーカスを復元する。
- ホームや地図から詳細を開いた場合、地図を含む探索画面は詳細表示中も保持する。同じタブで詳細を再読み込みした場合も、履歴に保存した探索状態を使って戻れるようにする。

## 履歴と状態の復元

- 画面を開く操作は `pushState` で履歴を1件追加し、現在の画面状態の保存は現在の履歴エントリーへの `replaceState` で行う。`popstate` の復元中に履歴を追加しない。
- 関連イベントを開いた後は、画面内またはブラウザの戻る操作で直前の詳細へ戻り、さらに戻ると元のホームまたは地図と探索状態へ戻る。進む操作では該当する詳細URLを再表示する。
- アプリ内で作った直前画面の履歴情報がある詳細だけ、画面内の戻るで履歴を戻る。ブックマーク・外部サイト・新規タブなどから直接開いた詳細では、画面内の戻るはホームへ移動し、その詳細履歴をホーム表示に置き換える。ブラウザの戻るはブラウザ本来の履歴に従う。
- URLを画面種別の基準とし、URLと合わない・壊れている・未知バージョンの復元情報は使わない。別タブへ探索状態を引き継がず、復元できるイベントや要素がなくなった場合は有効な画面要素へフォーカスを戻す。
- スクロール直後にブラウザで戻り、再読み込みしてから進む場合に備え、非アクティブになった履歴の最終スクロール位置は同じタブのsessionStorageで補助保存する。履歴へ書き戻した時点で補助データを削除し、保存が利用できない環境でも通常の履歴操作は継続する。
- 絞り込み・プロフィール・経路選択のダイアログ開閉状態は復元しない。リロード復元のために位置情報の取得や許可要求を自動実行しない。

## URL・SEO

- 公開URLは `events/{routeId}/` とする。`routeId` は初回公開後に保持し、イベント名・日付などの可変情報を更新しても、イベント固有の公式ページが同一である限り変更しない。
- GitHub Pagesでの直接アクセスに対応するため、ビルド時に全イベントの `index.html` を事前生成する。
- 各ページに固有のtitle、description、canonical、OGP、Event構造化データを付与し、`sitemap.xml` に収録する。

## データ契約

- 公開の最低条件は、名称、開催日、大阪府内である根拠、公式URL、出典または収集ソースである。
- 開催時間、終了時間、料金、予約、雨天対応、駐車場、最寄駅、交通、問い合わせ、SNSは公式ソースに明記された場合だけ保存する。
- 「不明」と「なし」を区別する。明記のない値は `false` にせず、未定義のまま保持する。
- 距離と所要時間は利用者の基準地点から算出した派生情報とし、公式情報と区別する。
- フィールド単位の根拠を `fieldEvidence` で保持できる構造にする。

## 開催状態

- 日付による「開催予定」「本日開催」「開催期間中」「終了」と、公式発表による「中止」「延期」「完売」「受付終了」を区別する。
- 公式発表の状態と根拠がある場合は、日付計算より優先する。

## デザインとアクセシビリティ

- `docs/DESIGN_CONTRACT_EDITORIAL.md` の生成り・朱・深緑・明朝系と8pxグリッドを継続する。
- ファーストビューに名称、状態、日時、会場を配置し、モバイルは経路と公式情報を下部に固定する。
- 主要操作は44px以上、キーボードフォーカスを可視化し、新しい詳細ページではh1へフォーカスを移す。
- 画像読み込み失敗、詳細の欠損、未登録URL、データ読み込み失敗の状態を表示する。

## 非対象

コメント、スレッド、ユーザー投稿、投稿写真などのコミュニティ機能は追加しない。

## 受け入れ条件

- ホーム・通常一覧・地図の各入口から簡易プレビューを挟まずに同じ詳細URLへ進め、詳細から関連イベントを開ける。
- 詳細A→関連イベントB→戻るA→戻る探索画面→進むA→進むBが、画面内とブラウザの操作で成立する。同じ詳細の連打で履歴が重複しない。
- 戻った探索画面で検索条件、地図と一覧の表示位置、展開件数、選択元のフォーカスが復元される。詳細URLの直接アクセスと同じタブでの再読み込みも成立する。
- 詳細→経路・公式サイトが操作できる。
- 390×844と1280×800で横はみ出しがない。
- typecheck、UIテスト、収集テスト、本番ビルドが成功する。
