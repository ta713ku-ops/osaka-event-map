# 比較・改善・再評価の実行計画

開始：2026-09-29。指示：改善後にGauntlet Loopで再評価し、両比較基準を上回るまで継続する。

基準資料は `docs/evidence/gauntlet-20260928/` に保持。旧版のビルド・データ・画像を残し、既存の未コミット変更を消さない。祭りどころのUIとWalkerplusの情報面を別々に評価したうえで、統合した最終版を独立批評者に渡す。批評者はLuna・推論max、実装担当とは別にする。

## 作業と判定

| 作業 | 所有する範囲 | 状態 | 確認条件 |
| --- | --- | --- | --- |
| 未掲載8件の公式調査・掲載 | 新規公式ソースモジュール・確認台帳。公開JSONの統合は親が担当 | done | 名称・大阪会場・会期を一次情報で確認し、未確認候補を公開しない。収集の再実行でも維持する |
| 共通詳細の7項目と画像内情報 | 詳細取得・根拠データ・会場台帳 | done | 日付、会場、紹介、時間、料金、予約、交通を調査。確認できた値が画面と検索に反映される。例外日や条件を落とさない |
| UIの残課題と内容の整合 | ホーム・カード・詳細・推薦 | done | 低解像度の拡大、タイトル切れ、画像と未確認表示の不一致を改善。今日・週末・夜の推薦を実データで点検 |
| 統合検証 | 親 | done | 型・ドメイン/UI・収集テスト、本番ビルド、URL/SEO、390×844と1280×800の操作・画面確認 |
| 独立再評価と次の改善 | 実装に関わらない批評者＋親の台帳記録 | done | 実物の匿名A/B、同じ条件、全ゲート通過、両基準に対する最終overall判定で改善版が選ばれる |

最初の固定9件は最低限の漏れ確認であり、全大阪の網羅性を代表するとは扱わない。次の比較では地域・ジャンル・今日/週末の別サンプルも加えて、固定9件だけに合わせた改善を避ける。追加サンプルと条件は候補改修前に固定する。

公式根拠がない時刻・料金・予約・座標を推測しない。Walkerplusや祭りどころの紹介文・画像・データを収集元へ転用しない。公開・SNS・課金導線は今回の改善ループに含めない。

勝利は独立評価とゲートの両方で記録する。tie、invalid、低信頼度、部分的勝利は完了として扱わず、最新の最大の差から次の改善を行う。独立批評者や必須資料を用意できない場合は、証拠付きで未完了を記録する。

2026-10-01の結果は[比較・独立判定](GAUNTLET_COMPARISON_20261001.md)を参照。固定18件は全件を監査表に残し、公式の掲載終了と予約期限を確認したSeaside Terraceだけを現在の発見性ゲートから除外した（対象17件）。最終の匿名全体判定は改善版、信頼度中、全6ゲート通過として台帳を`won`にした。この結果は固定画面・固定サンプルと共通詳細2件の範囲であり、大阪の全催しを網羅した証明ではない。
